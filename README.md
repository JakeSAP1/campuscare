# CampusCare

Система записи на консультации и психологическую поддержку студентов: психологи, карьерные консультанты и тьюторы университета вместо живой очереди и телефона.

Учебный проект (вариант 6): vanilla JavaScript + Express + SQLite, без сборки и фреймворков.

## Что умеет

- **Роли.** Студент и специалист, регистрации и вход с сессиями (пароли — scrypt, доступ — Bearer-токены).
- **Запись.** Специалист выбирает тип консультаций (психолог / карьерный / тьютор), специализацию, формат приёма (онлайн/очно), часы работы. Слоты генерируются на 14 дней вперёд.
- **Анкета.** Перед первой консультацией у специалиста студент заполняет анкету (курс, запрос, опыт) — она видна специалисту в заявке, а студент может открыть и поправить её, пока заявка не подтверждена.
- **Согласование времени.** Заявка создаётся в статусе «ожидает подтверждения»; специалист подтверждает, предлагает другое время (перенос) или отменяет — вторая сторона получает уведомление и подтверждает новое время.
- **Кабинет студента.** Вкладки: «Консультации» (предстоящие, история, отмена, повторная запись, сводка числами), «Заметки» (личный список — добавить, изменить, удалить), «Профиль» (имя, смена пароля).
- **Кабинет специалиста.** Вкладки «Расписание» (заявки, подтверждённые, архив, приватные заметки по консультациям, список клиентов) и «Профиль».
- **Отзывы.** После проведённой консультации студент оставляет анонимную оценку 1–5; рейтинг и список отзывов видны в каталоге и на карточке.
- **Уведомления.** Колокольчик в шапке и отдельная страница: новые заявки, подтверждения, отмены, переносы, отзывы; напоминание о консультации за 24 часа приходит и в колокольчик, и баннером в кабинете (сервер проверяет расписание раз в минуту, без дублей).
- **Мобильная версия.** Интерфейс подстраивается под узкий экран: одна колонка, панели на всю ширину, скролл вкладок.

## Запуск

```
npm install
npm start        # http://localhost:3000
```

При первом запуске создаётся база SQLite `data/campuscare.db` с демо-данными: 6 специалистов, студенты, слоты на 14 дней, история консультаций с отзывами. Чтобы начать с чистого листа — остановите сервер и удалите файл `data/campuscare.db` (вместе с `-wal`/`-shm`, если есть).


## API (кратко)

Документация в формате OpenAPI с интерфейсом Swagger: **http://localhost:3000/api/docs** (файл спеки — `server/openapi.json`, сырая спека — `/api/openapi.json`).

- `POST /api/register`, `POST /api/login`, `POST /api/logout`, `GET /api/me`, `PATCH /api/me`, `POST /api/me/password`
- `GET /api/specialists?type=&format=`, `GET /api/specialists/:id`, `/:id/slots`, `/:id/reviews`
- `POST /api/bookings`, `GET /api/my/bookings`, `GET /api/my/schedule`, `GET /api/my/clients`, `GET /api/my/stats`
- `POST /api/bookings/:id/confirm | cancel | reschedule | complete | spec-note`, `PUT /api/bookings/:id/questionnaire`
- `POST /api/reviews`
- `GET /api/notifications`, `POST /api/notifications/read`, `POST /api/notifications/:id/read`
- `GET /api/my/notes`, `POST /api/my/notes`, `PATCH|DELETE /api/my/notes/:id`

Доступ проверяется по роли: расписание и заметки по консультациям — только специалисту, записи и отзывы — только студенту.

## Схема базы данных

Хранилище — SQLite (встроен в Node.js, файл `data/campuscare.db`, создаётся при первом запуске). Семь таблиц:

| таблица | что хранит | связи |
|---|---|---|
| `users` | обе роли; у специалиста — тип, специализация, био, форматы, часы приёма | — |
| `sessions` | активные входы (токены) | `user_id → users` |
| `slots` | приёмные окна на 14 дней: время, длительность, свободен/занят | `specialist_id → users` |
| `bookings` | заявки: время, формат, статус (pending → confirmed → completed / cancelled), анкета, заметки, причина отмены | `student_id`, `specialist_id → users`, `slot_id → slots` |
| `reviews` | анонимные оценки 1–5, одна на проведённую запись | `booking_id → bookings` (уникально), `specialist_id`, `student_id → users` |
| `notes` | личные заметки из кабинета | `user_id → users` |
| `notifications` | колокольчик: тип, текст, прочитано | `user_id → users` |

Ключевые ограничения на уровне базы: e-mail уникален, оценка от 1 до 5, один отзыв на запись, статус записи и слота проверяются CHECK-условиями, чужие ссылки невозможны (внешние ключи). Удаление пользователя каскадно убирает его сессии, заметки и уведомления. Полное DDL — в `server/db.js`.
